# Редизайн розділу «Управління домом» — робочі документи

**Порядок читання для LLM:**

1. `IMPLEMENTATION_PLAN_HOUSE_MANAGEMENT.md` — головний документ. Покроковий план (Блок A — заміна, Блок B — нові фічі),
   інваріанти безпеки, реєстр команд. Один крок = один чат = один коміт.
2. `TZ_HOUSE_MANAGEMENT_REDESIGN_v2.md` — специфікація: як має виглядати кожен екран (фази Ф1–Ф5).
3. `UX_AUDIT_HOUSE_MANAGEMENT.md` — аудит поточного стану: що саме зламано і чому.
4. `mockup/OSBB-House-Management-DS.readable.html` — візуальний еталон у читабельному вигляді (можна грепати).
   `mockup/OSBB-House-Management-DS.html` — той самий макет, запакований, для перегляду в браузері людиною.

**Файли, які створює сама LLM на кроці A0 (не редагувати вручну):**
- `COMMANDS_BASELINE.txt` — зліпок усіх dispatch-викликів до редизайну. Контроль: у Блоці A diff має бути порожнім.
- `ACTIONS_INVENTORY.md` — таблиця дій по розділах і статусах. Контракт: у Блоці A набір дій не змінюється.

**Головне правило:** тип команди — це `${HandlerKey}.${string}`, тому TypeScript НЕ ловить неіснуючі команди.
Джерело істини — `commands: {...}` у `src/modules/content-engine/v2/handlers/<key>/handler.ts`
та реєстр у додатку 1 плану. Вигадувати команди заборонено.

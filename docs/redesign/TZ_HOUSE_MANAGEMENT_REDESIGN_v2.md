# ТЗ для Claude Design — Радикальный редизайн раздела «Управление домом»

**Проект:** OSBB Platform (Next.js App Router + Supabase, Architecture 2.0 / Command Bus)
**Область:** админка `app/(admin)/admin/(protected)/houses/[id]` + все workspace-компоненты `src/modules/houses/components/*` + общие примитивы `src/shared/ui/admin/*`.
**Приложения к этому ТЗ:** `UX_AUDIT_HOUSE_MANAGEMENT.md` (полный аудит текущего состояния — обязательно к прочтению) + zip-слепок репозитория с дизайн-системой и кодом раздела.
**Язык интерфейса:** украинский. Комментарии в коде — как принято в репо.
**Платформа:** desktop-first. Мобильная адаптация — не приоритет: ничего не должно ломаться на ~1024px, но специальные мобильные паттерны не проектируем. Пользователи — на Windows (горячие клавиши через Ctrl).

## 0. Роль и режим работы

Ты — Senior Product Designer/Engineer. Задача — **радикальный редизайн UX/UI** ключевого раздела платформы («Управление домом», ~85% рабочего времени пользователей), доведя его до уровня зрелых управляющих систем (Linear/Notion-класс по аккуратности взаимодействий), **строго на существующей дизайн-системе** проекта (токены `--cms-*`, радиусы `--r-*`, шрифты Inter/Lora, тёмная «золотая» тема как основная + светлая тема).

Пользователь платформы — менеджер управляющей компании, который ведёт десятки (цель — 100) домов: много однотипного контента, повторяющиеся действия, пакетные операции. Платформа должна вести с ним полный диалог: каждое действие имеет видимый отклик — загрузка, успех, ошибка, возможность отмены.

Работа разбита на фазы Ф1–Ф5. Внутри фазы — задачи; каждая задача завершается проверкой приёмочных критериев. Ничего за пределами scope фазы не трогать.

## 1. Жёсткие ограничения — НЕ ТРОГАТЬ

Это правило важнее любого дизайн-решения. Бизнес-логика и бекенд остаются нетронутыми:

1. **Команды и их payload'ы.** Единственный способ изменить данные — `useAdminContentCommand().dispatch({ type, houseId, payload })`. Полный union типов команд: `src/modules/content-engine/v2/types/commands.ts`. Запрещено: создавать новые типы команд, менять структуру payload, создавать server actions, вызывать supabase напрямую для записи (исключение: существующий client-side upload файлов в storage — он остаётся как есть).
2. **Сервисы чтения** (`src/modules/houses/services/getAdmin*`) не изменяются. Разрешено (согласовано): добавить **новые read-only сервисы** для счётчиков (см. Ф2.4) — только SELECT/count, `noStore()`, по образцу существующих сервисов; никаких изменений схемы БД, RLS, миграций.
3. **Публичная часть** (`app/(public)`, `Pub*`-компоненты, `public-theme.css`) — вне scope, не открывать.
4. **RBAC:** флаги `readOnlyMode` / `canConfirm` / `canArchive` / `canDelete` / `canChangeWorkflowStatus`, приходящие в workspace-пропсах, должны продолжать управлять доступностью тех же действий. Логику `getResolvedAccess` не менять.
5. **Порядок вызова команд** в сложных флоу сохранить (пример из reports: upload PDF → `create` → опционально `publish`; из meetings: `update` → lifecycle-команда). Разрешено оборачивать существующие последовательности в новые UI-флоу (bulk, duplicate+publish), но каждая единичная операция — это существующая команда с существующим payload.
6. **Дизайн-токены** из `app/globals.css` — единственный источник цветов/радиусов/теней. Новые компоненты не вводят хардкод-цветов. Допустимо добавлять новые токены-производные, если чего-то не хватает (например, `--cms-skeleton`), объявляя их для обеих тем.
7. Optimistic locking сохраняется: все update/publish/archive/delete передают `lockVersion` как сейчас; обработка `STALE_CONTENT` — см. Ф1.4.

**Разрешённые изменения кода за пределами чистого UI:** удаление мёртвого UI-легаси (см. Ф2.6), новые read-сервисы счётчиков (Ф2.4), localStorage-хелперы предпочтений.

## 3. Ф1 — Foundation: унификация примитивов

Цель фазы: один компонент = одна реализация на все 13 разделов. После Ф1 в workspace-ах не остаётся рукописных копий табов/баджей/кнопок.

### Ф1.1 Табы
`AdminSegmentedTabs` — единственная реализация вкладок-фильтров. Удалить 4 рукописные копии pill-табов (reports, plan, debtors, specialists). Добавить компоненту: клавиатурную навигацию стрелками (roving tabindex), пропс `size` при необходимости. Счётчики на вкладках — оставить везде, где есть, и добавить, где нет.

### Ф1.2 Статусы — единая карта
Единственный источник: `AdminStatusBadge` + исправленный `statusToneFor`. Зафиксировать:

| lifecycle | Лейбл | Тон |
|---|---|---|
| draft | Чернетка | warning |
| published | Опубліковано | success |
| archived | Архів | neutral |

Исправить `statusToneFor`: `archived → neutral` (сейчас danger — ошибка). Workflow-статусы плана/зборов: `planned → info («Заплановано»)`, `in_progress → warning («В роботі»)`, `completed → success («Виконано»)`, этапы зборов — `active → info («Голосування»)`, `review → warning («На перевірці»)`, `completed → success («Завершені»)`. Удалить все локальные `getStatusTone`/`getStatusBadgeClasses`/рукописные span-баджи. Терминология действий везде: **«Опублікувати»** (не «Підтвердити»), «В архів», «Відновити», «Видалити», «Зберегти».

### Ф1.3 Кнопки и канонический футер форм
Все кнопки — через `Button`/`adminButtonClasses`/`IconButton`. Канонический футер панели редактирования (един для всех разделов), sticky снизу панели:

```
[Зберегти]primary  [<lifecycle-действие>]        …спейсер…        [Видалити]danger
```
- lifecycle-действие по статусу: draft → `Опублікувати` (success); published → `В архів` (secondary); archived → `Відновити` (secondary).
- `Видалити` показывается только для draft/archived (danger, справа, отделена).
- Кнопки «Скасувати» нет: закрытие — ×, Esc, клик по оверлею (через dirty-guard, Ф3.5).
- Pending-состояния: label меняется («Зберігаємо…»), спиннер в кнопке, остальные кнопки disabled. Убрать `overflow-x-auto` с панелей кнопок.
- Publish/archive/delete — по-прежнему через `PlatformConfirmModal` с существующими тонами.

### Ф1.4 Тосты 2.0 (единый канал диалога)
Переписать `ToastProvider` (`src/shared/ui/toast/ToastProvider.tsx`), API совместимо расширить:
- Позиция снизу-справа, стек до 3 (старые вытесняются), появление/уход с motion-safe анимацией.
- Структура: иконка тона, title, description, кнопка ×, опциональная **action-кнопка** `{ label, onClick }`.
- `success`: автозакрытие 3.5с, пауза таймера при hover.
- `error`: **без автозакрытия**, закрывается только вручную.
- `info`: 5с.
- Спец-обработка `STALE_CONTENT` в `useAdminContentCommand`: тост «Дані застаріли» + описание «Хтось змінив цей запис. Оновіть дані та повторіть.» + action «Оновити дані» → `router.refresh()`.
- Из workspace-ов удалить инлайн-блоки `workspaceError ?? lastError` (двойной показ). Инлайн остаётся только как валидация под конкретным полем.
- `useAdminContentCommand`: `lastError` больше не рендерится напрямую в workspace-ах; хук остаётся API-совместимым.

### Ф1.5 FileDropzone 2.0
Единый компонент загрузки файлов (доработать существующий `FileDropzone`): зона drag-and-drop + кнопка выбора; после выбора — карточка файла (иконка типа, имя, размер, ×); для существующего файла — состояние «Поточний файл» с действиями «Замінити» / «Видалити» (замена помечается «Буде замінено після збереження», удаление — «Буде видалено після збереження», с возможностью отменить пометку); состояние ошибки валидации под зоной; раздельные фазы прогресса: «Завантаження файлу…» (client upload) → «Збереження…» (dispatch). Использовать во всех местах загрузки: reports (PDF), announcements (PDF), plan (фото + PDF, мультизагрузка), documents (PDF), debtors (импорт — можно оставить кнопкой). Логику загрузки (client-side supabase upload, payload с `{bucket, path, originalName, size}`) не менять.

### Ф1.6 EmptyState
`EmptyState` во всех пустых списках: иконка раздела, заголовок, 1 строка описания, CTA «Створити <сущность>» (открывает панель создания; скрыт при `readOnlyMode`). Для вкладки «Архів» — без CTA. Удалить рукописные dashed-блоки.

### Ф1.7 Даты — единый формат
Утилита `formatAdminDate` (новый файл в `src/shared/utils/`): списки/карточки → `16 лип. 2026`; детали/панель → `16 липня 2026, 14:30`; относительное «щойно/5 хв тому» не вводим. Локаль **только uk-UA**. Убрать все `toLocaleString("ru-RU")` (HouseAnnouncementsWorkspace, EditAnnouncementSectionForm) и разнобой форматов.

### Ф1.8 Локаль-фиксы

Убрать из UI техническую кнопку «Синхронізувати категорії» (reports) — вызывать `reports.categoriesUpsert` автоматически внутри существующего флоу сохранения отчёта с новой категорией, без отдельной кнопки. ## 5. Ф3 — Эталонный workspace: «Оголошення»

Announcements переписывается первым как эталон; Ф4 тиражирует его паттерн. Структура экрана раздела (сверху вниз): панель управления списком → список. Никаких инлайн-форм в потоке страницы.

### Ф3.1 Панель управления списком
Одна строка: слева `AdminSegmentedTabs` lifecycle (Опубліковані / Чернетки / Архів + счётчики); правее — поиск (иконка, placeholder «Пошук…», hotkey `/`), селект сортировки (Новіші / Старіші / Назва А-Я), переключатель вида **рядки/сітка** (два icon-toggle), кнопка `[+ Нове оголошення]` primary. На вкладке «Архів» primary-кнопка **не исчезает** (создание всегда доступно), а справа от неё появляется secondary-danger «Видалити все» (с существующим confirm). Вторая строка (при наличии): фильтры-чипы раздела (Ф4-таблица).

### Ф3.2 Row-card (вид «рядки», дефолт) + Grid (вид «сітка»)
**Row-card** — `<div>` (не button), full-width, компактный:
- Слева: строка баджей (`AdminStatusBadge` + чипы раздела, для объявлений — уровень: точка+лейбл «Важливе/Звернути увагу/Звичайне» с danger/warning/success-*text*-токенами) → заголовок (semibold, 1 строка, truncate, выделяется мышью) → превью 1 строка muted → мета-строка: `Оновлено 16 лип. 2026 · Опубліковано 14 лип. 2026 · 📎 PDF`.
- Справа: зона **быстрых действий** — icon-кнопки по статусу, видимы всегда (приглушённые, hover — активные), каждая с tooltip:
  - draft: `Опублікувати` (publish-иконка) · `Видалити`;
  - published: `В архів` · `Створити на основі` (copy-to-draft, существующий duplicate в свой дом);
  - archived: `Відновити` · `Видалити`.
  - Все опасные/lifecycle — через существующие `PlatformConfirmModal`; клики по иконкам не открывают панель (stopPropagation).
- Клик по остальной площади строки → панель редактирования. Курсор pointer, hover — border-strong + фон elevated. Убрать нумерацию «Оголошення #N».

**Grid** — та же карточка в 2-колоночной сетке, превью 2–3 строки. Переключение вид/вкладка/фильтры/сортировка запоминаются в localStorage per-раздел (`osbb.ws.<section>.v1`) — вернувшись в раздел, пользователь видит своё последнее состояние.

### Ф3.3 Список: «Показати ще»
Рендер порциями по 20 с кнопкой «Показати ще 20» и строкой «Показано 20 з 137». Поиск/фильтры/сортировка применяются **ко всему** набору (данные уже на клиенте), порционность — только рендер. При активном поиске счётчик отражает найденное.

### Ф3.4 Панель создания/редактирования (`AdminSidePanel`)
Все create/edit — только в боковой панели:
- Ширина: стандарт `max-w-2xl`; широкая `max-w-4xl` для збори/правління/публикаций (Ф4).
- Sticky-шапка: заголовок («Нове оголошення» / название записи), под ним `AdminStatusBadge` + «Оновлено {дата}»; справа — блок `ContentWorkspaceActionButtons` (copy + duplicate по домам, для published/archived) и ×.
- Тело: скролл; поля через `FormField`/`Input`/`Textarea`/`Select`/`FileDropzone`; обязательные поля помечены `*`; inline-валидация под полем (пустой заголовок и т.п.) до вызова команды.
- Sticky-футер: канонический (Ф1.3).
- Закрытие: ×, Esc, оверлей — все через dirty-guard.
- После **любого успешного действия панель закрывается**, тост подтверждает; тосты lifecycle-действий — с Undo (Ф5.1).
- Открытие панели редактирования — мгновенное (данные записи уже на клиенте), никакой перезагрузки.

### Ф3.5 Dirty-guard
Хелпер `useDirtyGuard` (сравнение snapshot формы с исходным): при попытке закрыть панель/сменить lifecycle-вкладку/уйти на другой раздел/сменить дом с непустыми изменениями — `PlatformConfirmModal` «Є незбережені зміни» / «Якщо закрити, зміни буде втрачено.» / `[Закрити без збереження]`(danger) `[Повернутись]`. Плюс `beforeunload` при dirty-панели.

### Ф3.6 Хоткеи раздела
`N` — открыть панель создания; `/` — фокус в поиск; `Esc` — закрыть панель/поповер (есть); `Ctrl+Enter` — «Зберегти» в открытой панели. Игнорировать, когда фокус в инпуте (кроме Ctrl+Enter/Esc). Подсказки — в tooltip'ах кнопок («Нове оголошення · N»).

**Приёмка Ф3 (эталон):** полный цикл create→publish→archive→restore→delete проходит только через панель и quick actions; те же команды и payload'ы, что до редизайна (`announcements.create/update/publish/archive/restore/delete/deleteAllArchived/duplicate`); клик по карточке в конце длинного списка открывает панель без прокрутки страницы; несохранённые правки нельзя потерять молча; ошибка команды видна до ручного закрытия; состояние вкладки/вида восстанавливается при возврате.

## 7. Ф5 — Продуктивность («1 менеджер = 100 домов»)

### Ф5.1 Undo в тостах
После quick action / lifecycle-действия success-тост получает action «Скасувати», диспатчащий обратную команду с актуальным `lockVersion` из результата: publish↔archive… → обратные пары `archive/restore/publish` (delete необратим — без Undo). Окно действия — время жизни тоста (3.5с, hover продлевает).

### Ф5.2 Duplicate → «Опублікувати одразу» (топ-приоритет)
В `CrossHouseDuplicatePanel` добавить чекбокс «Опублікувати копії одразу після створення». Флоу: существующий `*.duplicate` по выбранным домам → для каждого созданного черновика существующий `*.publish` (последовательно). Прогресс в панели: полоса + «Опубліковано 34 з 100», по завершении — итог: успехи и список домов с ошибками (с текстами), кнопка «Повторити для домів з помилками». Панель нельзя закрыть во время выполнения (или предупреждение).

### Ф5.3 Bulk-режим списка
Кнопка «Вибрати» в панели управления списком → чекбоксы на карточках + «выбрать все на вкладке». Плавающая панель снизу: «Вибрано N» + действия по текущей вкладке: Чернетки → `Опублікувати всі` / `Видалити`; Опубліковані → `В архів`; Архів → `Відновити` / `Видалити`. Выполнение — последовательный цикл существующих единичных команд с прогресс-оверлеем (`PlatformSectionLoader`) и итоговым тостом («Опубліковано 12, помилок: 1»). Один общий confirm перед стартом.

### Ф5.4 «Створити на основі» (copy-to-draft) на карточке
Уже включено в quick actions (Ф3.2): для published/archived — иконка копии, существующий duplicate в текущий дом, тост «Чернетку створено» с action «Відкрити» (переключает на вкладку Чернетки и открывает панель новой записи).

### Ф5.5 Строка состояния дома ⚙
В шапке под названием: `● 5 чернеток · ● 2 заявки · ● 1 задача` (данные из `getHouseSectionCounters` + счётчик задач). **Решение ревью:** счётчик задач включаем, только если он доступен без новых зависимостей/сервисов; иначе строка = чернетки + заявки. Каждый элемент кликабелен: черновики → открывает меню-поповер «в яких розділах» с переходами; заявки → раздел Спеціалісти. Нули не показываются; при полном нуле строка скрыта.

### Ф5.6 Панели шаблонов в новой ДС
`ContentTemplateSlotsPanel` и вызовы шаблонов (FAQ, публикации, специалисты) перевести на новые примитивы: та же `AdminSidePanel`, row-card'ы шаблонов, канонические кнопки, тосты. Функциональность и команды (`*.applyTemplate`, `templates.upsert`) без изменений. Новые типы шаблонов **не** добавлять (бэклог).

### Ф5.7 Свод хоткеев (Windows-first)
`N`, `/`, `Esc`, `Ctrl+Enter` — из Ф3.6, работают во всех разделах. Мини-подсказка «?» не делаем (бэклог), но tooltips обязательны.
